# Метрики ефективності — наукова нотація

Цей документ — єдине джерело істини для назв коефіцієнтів і формул, що
використовуються у платформі. Усі звіти, експорти, API-поля та змінні коду
дотримуються цієї нотації.

## Загальні позначення

| Символ | Розшифровка | Тип |
|---|---|---|
| `N_sorties` | Кількість пусків (запущених виробів) за період | int |
| `N_success` | Кількість виробів, які виконали польотне завдання | int |
| `N_lost` | Безповоротно втрачені | int |
| `N_repair` | Повернуті в ремонт | int |
| `N_loss_external` | Втрати, віднесені до **зовнішньої зони** (РЕБ, бойові фактори) | int |
| `N_loss_manufacturer` | Втрати, віднесені до **виробничої зони** (відмови вузлів) | int |
| `N_crew_loss` | Втрати + повернення у ремонт, віднесені до **зони обслуги** | int |

## Ключові показники

| Код у системі | Грецька | Назва | Формула |
|---|---|---|---|
| `MSR` | **η** | Mission Success Rate | `N_success / N_sorties` |
| `MSR_c` | **η_c** | Crew-adjusted MSR | `N_success / (N_sorties − N_loss_external − N_loss_manufacturer)` |
| `CLR` | **λ_c** | Crew Loss Rate | `N_crew_loss / N_sorties` |
| `ΔMSR` | **Δη** | Зміна MSR vs попередній період, у в.п. | `(MSR_curr − MSR_prev) × 100` |

> **Зауваження.** `MSR_c` — це «очищений» показник: знаменник виключає ті
> пуски, де втрата сталася через фактори поза контролем обслуги (зовнішні
> впливи, конструктивно-виробничі відмови). Саме він використовується для
> рейтингу експлуатантів і тригера T1.

## Назви в інтерфейсі та звітах

Грецькі символи лишаються нотацією документа й коду — **в інтерфейсі їх немає**.
Причина проста: ніде на екрані вони не були розшифровані, тож для користувача
`η_c` не значило нічого. Єдине джерело UI-назв — `apps/web/src/lib/metrics.ts`;
пояснення для користувача — «Настанова користувача» §5
(`docs/passport/03-instrukciya-korystuvacha.md`).

| Код | Нотація | Назва в UI | Коротка (колонки таблиць) | Заголовок XLSX/PDF |
|---|---|---|---|---|
| `msr` | η | Успішність застосувань | Успішність | `Успішність, % (η)` |
| `msr_c` | η_c | Успішність у зоні обслуги | Успішність (обслуга) | `Успішність обслуги, % (η_c)` |
| `clr` | λ_c | Втрати з вини обслуги | Втрати (обслуга) | `Втрати обслуги, % (λ_c)` |
| `delta_msr_pp` | Δη | Зміна успішності | Зміна, в.п. | `Зміна, в.п. (Δη)` |
| `msr_narrow` | η_narrow | Успішність без зривів | Без зривів | — |
| `msr_full` | η_full | Успішність з урахуванням зривів | Зі зривами | — |

Правила:

- **UI** — тільки українська назва; формула й символ віддаються підказкою
  (`title`) з `METRIC.*.hint`. Нової назви без запису в `metrics.ts` бути не може.
- **XLSX/PDF** — назва + символ у дужках, плюс блок «Позначення» під таблицею
  (`LEGEND_*` у `services/exports.py`): друкований звіт має читатися без
  супровідних документів.
- **API, БД, код** — незмінно `msr` / `msr_c` / `clr` / `delta_msr_pp`.
- **`aborted` → «зрив», не «аборт».** У коді й API поле лишається `aborted` /
  `abort_reason` (mission abort — стандартний авіаційний і NATO-термін).
  Українською його передаємо словом **зрив** (зрив завдання до запуску):
  «аборт» у мові однозначно зайнятий медичним значенням і в документі для
  підрозділу читається недоречно.

## Рейтинг експлуатантів

Класифікація за `MSR_c` (η_c):

| Категорія | Поріг |
|---|---|
| **high** (висока готовність) | η_c ≥ 0.85 |
| **ok** (задовільна) | 0.70 ≤ η_c < 0.85 |
| **needs_training** (потребує до-підготовки) | η_c < 0.70 |
| **insufficient_data** (замало даних) | < 10 запусків, незалежно від η_c |

> **Знаменник іде разом із числом (ADR-027).** `OperatorRating` несе `sorties`,
> `cleaned_denominator` і `sample_sufficient`. Частка без розміру вибірки — це
> твердження, а не вимірювання, і рейтинг іде командиру. Поріг
> `MIN_SORTIES_FOR_VERDICT` — задокументована політика, не статистичний
> результат: з ним можна сперечатися, і саме тому він названий.

## Назви тригерів

| Тригер | TriggerType (DB) | Умова |
|---|---|---|
| T1 | `msr_drop` | η_c < 0.70 три доби поспіль |
| T2 | `repeated_reason` | Та сама причина ≥ 3 разів за 7 діб |
| T3 | `item_anomaly` | Серійний № отримав ≥ 2 ремонти/втрати за 30 діб |
| T4 | `enterprise_drop` | η підприємства впав > 10 в.п. day-over-day |
| T5 | `manual` | Створено вручну |

## Маппінг старих назв (для довідки)

Платформа раніше використовувала українські короткі назви; з версії
`v0.6.0-metrics` всі вони замінені:

| Стара назва | Нова |
|---|---|
| Кеф | MSR (η) |
| Кеф_обсл | MSR_c (η_c) |
| Кв_обсл | CLR (λ_c) |
| Δ Кеф | ΔMSR (Δη) |
| keff_drop (trigger) | msr_drop |

## Дотримання у коді

| Місце | Як використовувати |
|---|---|
| Pydantic-схеми | поля `msr`, `msr_c`, `clr`, `delta_msr_pp`, `msr_prev`, `msr_this` |
| SQLAlchemy моделі | `TriggerType.MSR_DROP` тощо |
| XLSX/PDF-заголовки | константи `H_MSR` / `H_MSR_C` / `H_CLR` / `H_DELTA` у `services/exports.py` |
| Підписи в інтерфейсі | `METRIC.*` з `apps/web/src/lib/metrics.ts` — не хардкодити |
| Документація | використовувати грецькі літери у формулах, латиницю — у назвах полів |
