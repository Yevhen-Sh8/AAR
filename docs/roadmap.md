# Дорожня карта реалізації

Орієнтовний термін — 12 тижнів від схвалення концепції до пілоту. Стек:
Python + FastAPI, React + Vite PWA, PostgreSQL, Redis, Docker Compose
(on-prem). Інтеграції в MVP — CSV/Excel імпорт від виробництва.

## Етап 0 — Концепція та схвалення (тиждень 1) — поточний

- Залити `docs/concept/AAR_v2.md`, `docs/normative/*`, `docs/forms/*`,
  `docs/automation.md`, `docs/roadmap.md`, оновлений `README.md` у гілку.
- Відкрити draft PR.
- Зафіксувати рішення зі стеку, середовища, ролей.

## Етап 1 — Скелет монорепо (тиждень 2)

- `apps/api` (FastAPI), `apps/web` (React PWA), `packages/shared` (типи,
  класифікатори), `infra/` (docker-compose, міграції alembic), `docs/`.
- CI: ruff/black, mypy, pytest, vitest, build, перевірка міграцій.
- Базовий auth (JWT), ролі: учасник, менеджер, аналітик, адмін,
  системний інтегратор.

## Етап 2 — Модель даних і довідники (тиждень 3)

- Сутності: `Item`, `ItemType`, `Operator`, `LossReason` (а–д),
  `RepairReason` (а–р), `ResponsibilityZone`, `UsageEvent`, `AARCase`,
  `Participant`, `IndividualReport`, `Recommendation`, `KnowledgeEntry`.
- Seed-дані за листопад–грудень (синтетика для тестів).
- Адмінка довідників.

## Етап 3 — Прийом подій і щоденна довідка (тиждень 4)

- REST `POST /events` + CSV/Excel імпорт.
- Materialized view η (MSR)/η_c (MSR_c).
- Генератор PDF/XLSX за Т.1–Т.3.
- Cron 23:59, розсилка.

## Етап 4 — Місячна звітність + рейтинг (тиждень 5)

- Т.4–Т.7, тренди, рейтинг експлуатантів.
- Кабінет аналітика: фільтри, drill-down від місяця до події.

## Етап 5 — AAR-кейси + тригери (тиждень 6)

- CRUD AAR-кейсу, форма індивідуального звіту (6 блоків v1.0).
- Engine правил T1–T5 (A6), auto-create cases.
- Нагадування A7.

## Етап 6 — LLM-автоматизація (тиждень 7)

- Claude API: A8 класифікація причин, A9 драфт висновків, A10 пошук аналогій.
- Prompt caching на класифікаторі та шаблонах звітів.
- Fallback на ручні режими, якщо API недоступний.

## Етап 7 — Offline-first PWA (тиждень 8)

- Service worker (Workbox), IndexedDB, sync-черга, конфлікт-резолюшн.
- Тести з вимиканням мережі.

## Етап 8 — Нормативні експорти (тиждень 9)

- Шаблони форм наказу № 440 (відомості, журнали, акти).
- Звірка реквізитного складу з додатками до Інструкції.

## Етап 9 — Інтеграції (тиждень 10+, опційно)

- DELTA / «Кропива» (експорт ситуаційних даних).
- SAP / «Оберіг» (звірка номенклатури та обслуг).
- Brave1 Market (довідник виробників).

## Етап 10 — Безпека, аудит, пілот (тиждень 11–12)

- Append-only лог + hash-chain (A12).
- RBAC, відповідність вимогам ISO/IEC 27001:2022 та ISO/IEC 27002:2022.
- Пілот на одному експлуатанті з реальними даними листопада–грудня.
- Acceptance: усі точки з §8 концепції відтворюються end-to-end.

## Контрольні точки якості

| Етап | Acceptance |
|---|---|
| 3 | Контрольний день з ручним розрахунком = звіт системи |
| 4 | Σ за добами = підсумок місяця |
| 5 | 3 поспіль падіння η_c (MSR_c) → авто-кейс |
| 6 | LLM-класифікатор ≥ 90 % accuracy на 50-ти ручних описах |
| 7 | 10 подій офлайн → авто-синхрон без втрат і дублів |
| 8 | Реквізити експортів збігаються з додатками до наказу № 440 |
| 10 | Hash-chain цілісність валідується аудитом |
